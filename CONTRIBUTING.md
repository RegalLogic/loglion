# Contributing

Thank you for helping make Log Lion better. Log Lion's source code is not public, so the
most valuable contributions are reports, ideas, and answers.

## Ways to help

- **Report bugs.** Use the [bug report form](https://github.com/RegalLogic/loglion/issues/new?template=bug_report.yml)
  and follow [SUPPORT.md](SUPPORT.md) on what to include.
- **Vote.** Add a 👍 to the issues you care about rather than a "+1" comment. We sort by
  votes when planning.
- **Ask for formats and features.** Tell us what you're trying to get done, not only the
  feature you have in mind. There's often more than one way to solve it.
- **Answer questions** in [Discussions](https://github.com/RegalLogic/loglion/discussions),
  and share filters, color schemes and Lua scripts in **Show and tell**.
- **Fix the documentation.** If a page in [docs](docs/README.md) is wrong or unclear, open
  an issue with the **Documentation** form, or a pull request against the Markdown. The
  docs here are generated from Log Lion's help, so we'll make the change at its source and
  credit you.

## How we handle issues

Every new issue is labeled **triage** until we've read it. We then label it and either:

- **confirmed**: we can reproduce it, or the request makes sense for Log Lion;
- **needs info**: we need more from you. Issues waiting on information for 14 days may be
  closed, and reopened when it arrives;
- **duplicate**: closed with a link to the issue it duplicates;
- **not planned**: closed with an explanation.

When a fix or feature ships, we close the issue and the
[revision history](docs/revision-history.md) says which release it's in.

## Code of conduct

Be kind and assume good intent. Harassment, personal attacks, and spam are removed, and
repeat offenders are blocked. Report anything that concerns you to
[contact@regallogic.com](mailto:contact@regallogic.com).
